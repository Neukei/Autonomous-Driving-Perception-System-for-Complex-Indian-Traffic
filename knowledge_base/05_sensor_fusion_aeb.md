# Chapter 5: Spatial 2D LiDAR Fusion & Active AEB Decision Engine

## 1. Mathematical Formulation: 3D-to-2D Pinhole Projection

Instead of rendering a detached bird's-eye view (BEV) 2D scatter plot, DREIVE projects 2D polar LiDAR measurements directly into the camera frame coordinate space:

```
            [ Roof: RPLiDAR A1M8 (Elevation Z_lidar = 1.50m) ]
                           │
            (ΔZ = +0.25m, ΔX = 0m, ΔY = +0.15m forward)
                           │
            [ Cabin: Rearview Dashcam (Elevation Z_cam = 1.25m) ]
```

### Coordinate Conversion: Polar to Camera Frame
A LiDAR point with azimuth angle $\theta \in [0^\circ, 360^\circ)$ and radial distance $r \in [0.15\text{m}, 12.0\text{m}]$ is first converted to relative forward-centered radians $\theta_{\text{rel}} \in [-\pi, \pi]$:
$$\theta_{\text{rel}} = \begin{cases} 
\theta \cdot \frac{\pi}{180} & \text{if } \theta \le 180^\circ \\
(\theta - 360^\circ) \cdot \frac{\pi}{180} & \text{if } \theta > 180^\circ 
\end{cases}$$

Applying the vehicle coordinate transform:
$$Z_{\text{forward}} = r \cos(\theta_{\text{rel}} + \Delta\theta_{\text{yaw}})$$
$$X_{\text{lateral}} = r \sin(\theta_{\text{rel}} + \Delta\theta_{\text{yaw}})$$

### Projection into Image Pixel Column ($p_x$)
Using the pinhole camera projection matrix with horizontal focal length $f_x$:
$$p_x = c_x + \left(\frac{X_{\text{lateral}}}{Z_{\text{forward}}}\right) f_x = \frac{W}{2} + \left(\frac{W / 2}{\tan(\text{FOV}_h / 2)}\right) \cdot \tan(\theta_{\text{rel}})$$

If $|\theta_{\text{rel}}| \le \frac{\text{FOV}_h}{2}$ ($39^\circ$) and $Z_{\text{forward}} > 0.1\text{m}$, the return maps to a valid optical pixel column $0 \le p_x < W$.

## 2. Object Association & Outlier-Rejection Ranging

For every optical bounding box $[x_1, y_1, x_2, y_2]$ generated by YOLO11s:
1. All projected LiDAR points falling within horizontal span $x_1 \le p_x \le x_2$ are collected into a distance bucket $\mathcal{D} = \{Z_1, Z_2, \dots, Z_k\}$.
2. **Median Cluster Filtering**: To reject background reflections and ground edge dropouts:
   $$\text{Distance} = \text{median}\left(\text{sort}(\mathcal{D})[: \lceil k / 2 \rceil]\right)$$
   This guarantees that distance estimation tracks the **closest solid surface** of the vehicle rather than roadside background clutter.

## 3. Dynamic Ground Distance Tracer Lines

In the Mission Control viewport, DREIVE visualizes spatial proximity using **laser tracer vectors**:
- **Vehicle Origin Anchor**: Bottom center of windshield ($p_{\text{origin}} = (W/2, 0.98 \times H)$).
- **Target Contact Point**: Ground centroid of the bounding box ($p_{\text{target}} = ((x_1 + x_2)/2, y_2)$).
- **Range Gradient**:
  - $\text{Green} \ge 6.5\text{m}$: Safe following distance.
  - $\text{Yellow/Amber } 3.0\text{m} \le d < 6.5\text{m}$: Closing distance alert.
  - $\text{Red Glowing } d < 3.0\text{m}$: **Critical proximity alert**.

## 4. Autonomous Emergency Braking (AEB) Logic

```
┌──────────────────────────────────────────────────────────┐
│                   AEB DECISION MATRIX                    │
│                                                          │
│   Target In Forward Path? (0.35 < c_x < 0.65)            │
│            │                                             │
│            ├──▶ NO  ──▶ NORMAL CRUISE                    │
│            │                                             │
│            └──▶ YES ──▶ Check LiDAR Distance:            │
│                           │                              │
│                           ├──▶ > 7.0m  : CLEAR (Green)   │
│                           ├──▶ 3.0–7.0m: WARNING (Amber) │
│                           └──▶ < 3.0m  : CRITICAL HALT   │
│                                          (Red Banner)    │
└──────────────────────────────────────────────────────────┘
```

The $3.0\text{ meter}$ critical threshold ensures that an emergency stop command is issued before physical collision occurs, accounting for the Jetson Orin Nano's $28.5\text{ms}$ perception latency + vehicle mechanical hydraulic brake response time (~200ms).
